# 新AI接手续作与恢复步骤

## 取得代码和交接资料

```bash
git clone --branch backup/live git@github.com:Alston3825/banyuexuan-monorepo.git banyuexuan-recovered
cd banyuexuan-recovered
python3 tools/verify_backup.py
git tag --list 'ai-checkpoint/*' --sort=-refname
```

需要指定历史版本时，另建副本并checkout某个检查点标签；不要在用户有未提交工作时直接reset/checkout覆盖。SHA256校验失败立即停止并核实，不在错误源码上继续开发。

阅读顺序：`备份与交接/交接说明.md` → `AGENTS.md` → `docs/交接手册.md` → `docs/当前开发任务.md` → `docs/待完善清单.md` → 最新检查/测试报告。依据时间识别旧文档：旧手册中的桌面私钥路径已经失效，恢复说明和最新报告优先。不应将旧进度快照的Git版本当作当前开发版本。

## 恢复本机运行环境

1. Node建议24（与CI一致），Python3.9+，Docker；以各package及requirements为准。先确认端口5180/3000/8000的占用与对应目录，避免重复启动。
2. `npm ci` 安装monorepo依赖；`cd apps/api && npx prisma generate` 生成客户端。
3. 从用户安全配置恢复真实.env；`.env.example`只是格式示例，不含生产凭据。不得粘贴秘密到聊天。
4. 新机器需恢复/初始化本机MySQL与Redis，**不得因接手重建用户现有banyuexuan_dev或生产库**。新空库才运行迁移与seed；原机直接沿用既有数据卷。
5. AI服务新建虚拟环境，`pip install -r apps/ai-service/requirements.txt`，按手册启动；原机虚拟环境不能假定跨机器可搬运。
6. 启动API、前端和AI服务，前端使用5180端口；本机默认测试账号见AGENTS。生产密码不会由源码恢复。

## 验证并继续开发

- 前端 `cd apps/web && npx vue-tsc -b && npx vite build`。
- 后端 `cd apps/api && npm run build && npm test -- --runInBand`。
- AI `python -m pytest apps/ai-service -q`（使用装好依赖的虚拟环境Python）。
- e2e使用**全新独立测试库**，DATABASE_URL显式覆盖，先迁移、seed，种子测试密码按AGENTS设置，再 `npx jest --config test/jest-e2e.json --runInBand --forceExit`。
- 2026-11-20已有1项e2e失败，详见检查报告；恢复成功不等于这个问题已修复。
- 记录真实运行命令、结果及限制，写回当前任务。新需求先记录用户决定、验收条件和下一步，再实现。

## 恢复备份机制

新电脑先配置GitHub SSH权限（仓库必须仍是private），运行 `python3 tools/backup_checkpoint.py`。脚本使用隔离镜像，默认首次在 `~/.banyuexuan-project-sync/repos/ai` 初始化；如果远端已有历史而本机镜像不存在，应先按下节克隆，不能强推。

```bash
mkdir -p ~/.banyuexuan-project-sync/repos
git clone --branch backup/live git@github.com:Alston3825/banyuexuan-monorepo.git ~/.banyuexuan-project-sync/repos/ai
git -C ~/.banyuexuan-project-sync/repos/ai config user.name 'Alston project backup'
git -C ~/.banyuexuan-project-sync/repos/ai config user.email 'alston3825@users.noreply.github.com'
python3 tools/backup_checkpoint.py
```

已有镜像推送冲突时先保留本地新快照、核对其他机器版本，不能force或自动覆盖。源文件读到一半发生变化时任务应失败并重试，不将不一致快照认作成功。

Codex每天四次自动化提示词保存在 `备份与交接/定时任务说明.md`。新AI/新电脑要在所用工具中重新创建调度，不能把说明文件存在当成任务已启动。GitHub定时任务读不到未上传的本机改动，因此不能代替本机备份。

## 生产数据与上线

服务器故障恢复按交接手册：先新建隔离环境恢复数据库和文件、核对数据与权限，再由用户决定切换。密钥及解密口令见资料边界，禁止上传到GitHub。只有用户明确说“上线”才按备份 → 推主分支 → 服务器拉取 → 部署 → 健康/业务验证流程执行。
