## 三、识别中发现的问题 / 需要注意的点

1. **“产妇常规护理计划”其实不是计划**，是服务执行打卡表 + 宣教签字单。建议拆开：新做的“护理计划”（版本制）+ 现有这张表变成“服务执行记录”（系统按计划和标准频次自动列出应做项，做完打钩，次数自动统计）。
2. 日常护理记录里**产妇的血压、脉搏没有专门栏**，护理师手写在边上；宝宝**黄疸值**也手写在总结栏。系统版会补成正式字段。
3. 入住天数、出生天数（日龄）、各项“共 N 次”**都可以由系统自动算**，不用手填。
4. 用药委托书缺**宝宝姓名、剂量、疗程**，纸质只有妈妈姓名；药名写“AD”之类简称，建议做常用药下拉。
5. 出所评估里呼吸、体重等有空栏没填——系统版可以设为“必填/选填”，减少漏项。
6. 手写字迹较潦草（姓名、药名、自由文本），**AI 识别必须保留人工复核**；勾选框和数字（体温、黄疸、血压）的识别相对可靠，自由文本要重点核对。

## 四、技术方案（给用户看的大白话版）

**存储方式**：7 类表格各建一套**正式的数据表**（体温、体重、黄疸、奶量、大小便次数、血压这些关键数字单独成列），而不是塞进一个万能表单。好处：后期筛选统计准确、快（例如“本月黄疸值超过 12 的宝宝”“剖宫产妈妈平均恶露天数”）。代价是开发量大一些，但值得。

**照片留档**：每张表可以挂 1~多张照片；和客户、入住记录、妈妈/宝宝档案关联；原件永久保存，之后修改数据不影响原件。手机相册里的 HEIC 照片系统自动转成通用格式。

**拍照识别 + 人工复核**（沿用合同模块已跑通的做法）：拍照上传 → AI 识别成草稿 → 打开“复核页”（左边原图、右边识别结果，识别没把握的字段标黄）→ 录入者逐项核对修改 → 点“确认入库”才写进正式数据。**没确认之前不会进入统计。**

**手机/电脑直接录入**：同一套表单页面，手机宽度做了适配；每日护理记录按“今天待填”清单进入，一天一份，系统按入住天数自动生成当天的空白记录，**住几天就有几份**，没填的会在护理看板上显示“今日未填”。

**用药委托书的多次变化**：每一份委托书是一个版本（含签字照片），变更/停药时新建一份并指向上一份，完整保留“谁在哪天委托了什么、后来怎么变”；日常记录里“用药”一栏可直接选当前有效的委托药品，做到“按委托给药”有据可查。

**护理计划（对应你前面的要求）**：护理长制定 → 护理主任审核 → 生效；每 7 天提醒护理长评审（写上阶段执行结果 + 调整后的新版本）；护理主任查房可随时发起调整；旧版本只读保留。护理等级暂分三级，每级的服务项和频次先参照医院三级护理，并以宣教里的标准频次做“三级（常规）”默认值，我拟好后给你审。
