# 前端性能基线报告

对应《伴月轩月子中心管理系统_软件项目开发计划_V1.0》P5阶段"性能安全+PWA+真实硬件"任务里的性能基线部分。

## 测量方法与范围

用生产构建（`npm run build` + `vite preview`，非`npm run dev`的HMR开发模式，反映真实部署后的资源体积/加载时机）+ 真实本地API（连本地开发数据库，不是mock数据），在浏览器里用Navigation/Resource Timing API采样了几个代表性页面：登录页（冷启动，无缓存）、客户列表页（登录后首次进入，触发认证+多个数据接口）、经营分析看板（本系统数据聚合量最大的页面）、房态看板（新增PWA离线缓存覆盖的页面之一）。

这是**单次本地测量**，不是生产环境多用户并发下的P95统计（当前没有真实用户流量、也没有接入APM），数值仅供当前迭代的相对基线参考——后续每次大改动后可以用同样方法重新测一次，比较是否变慢，而不是追求这次数值本身的绝对精确性。

## 测量结果

| 页面 | 场景 | DOMContentLoaded | load事件 | 本页资源传输量 | 关键接口耗时 |
|---|---|---|---|---|---|
| 登录页 | 冷启动（首次访问，无浏览器缓存） | 78ms | 83ms | 146KB（13个资源） | - |
| 客户列表 | 登录后首次进入（触发认证+3个数据接口） | - | - | 255KB | `/auth/login` 103ms、`/crm/customers` 39ms、`/platform/stores` 33ms、`/platform/accounts` 42ms |
| 经营分析看板 | 页面间跳转（浏览器已缓存公共chunk） | 54ms | 59ms | 0KB（全部命中浏览器缓存） | `/platform/stores` 29ms（页面本身的财务/房态聚合查询要点击查询按钮后才发起，本次未触发） |
| 房态看板 | 页面间跳转（浏览器已缓存公共chunk） | 23ms | 25ms | 1KB | `/room/rooms/board` 24ms、`/crm/customers` 28ms、`/platform/stores` 24ms |

结论：单用户、本地环境下，冷启动首屏在100ms内完成，页面间跳转（利用了浏览器资源缓存）在60ms内完成，接口本身的响应时间都在20-40ms量级（`/auth/login`因为要做密码哈希比对稍慢，103ms），暂时看不出明显的性能瓶颈。

## 构建产物体积（来自生产build输出）

- PWA预缓存总量：163个文件，合计1554KB（未压缩）——这是安装到主屏幕后离线可用的应用外壳总大小。
- 最大的几个JS chunk（gzip压缩后）：`auth`相关公共依赖chunk 300.88KB→97.99KB gzip（这是当前单个最大的chunk，主要是axios等核心依赖）、`AdminLayout` 100.4KB→24.31KB gzip、`DataTable`（Naive UI表格组件）94.58KB→26.72KB gzip、`Select` 48.98KB→13.49KB gzip。
- 得益于按路由代码分割（每个视图文件都是`() => import(...)`懒加载），首屏（登录页）实际只需要下载146KB，不需要一次性加载全部163个预缓存文件。

## 暂不处理的事项

- 没有做真实网络环境（3G/慢速WiFi节流）下的测量——当前月子中心场景（门店内Wi-Fi/有线网络）网络条件通常优于移动公网环境，且没有真实用户反馈"页面慢"的具体场景，本轮不做无的放矢的网络节流测试。
- 没有引入前端错误监控/性能监控SDK（如Sentry）——开发计划文档里这属于后续可观测性建设的一部分，且需要额外的账号/服务接入决策，超出"跑一次基线测量"的范围。
- 经营分析看板的实际聚合查询耗时（点击查询后的响应时间）未在本次测量中触发，如果后续该页面被反馈变慢，可以针对性单独测量这一步。
