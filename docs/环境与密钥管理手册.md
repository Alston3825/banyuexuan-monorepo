# 环境与密钥管理手册

对应《伴月轩月子中心管理系统_软件项目开发计划_V1.0》P0阶段要求的交付物，此前一直没有补——现在结合"上线准备"一起补上。这份手册面向产品负责人（你）自行操作日常运维，不需要懂代码，但需要照着做。

## 一、三套环境的关系

| 环境 | 用途 | 数据库 | 谁来用 |
|---|---|---|---|
| 开发环境 | 本地写代码/联调，随时可重建 | 本机docker-compose跑的MySQL/Redis，`banyuexuan_dev`库 | 只有开发时（AI助手）用 |
| 预发环境 | 上线前最后验证，数据脱敏或用测试数据 | 建议用腾讯云一个独立的小规格MySQL实例，或至少是独立的库名 | 你验收新功能用，不影响真实客户数据 |
| 生产环境 | 真实客户数据，正式对外服务 | 腾讯云云数据库MySQL正式实例 | 门店员工日常使用 |

**当前状态**：开发环境一直在用，成熟。预发/生产环境本轮"上线准备"才第一次真正搭建。如果你暂时人力/预算有限，最低限度可以先只搭"生产环境"跳过独立预发环境，但要清楚这样做的风险是：新功能第一次跑在真实客户数据库上，没有一个"数据脱敏但结构一致"的环境提前踩坑。

## 二、密钥清单与获取渠道

以下密钥/连接串生产环境都要配置到服务器上的 `.env.prod` 文件里（模板见仓库根目录 `.env.prod.example`），**这个文件本身绝对不能提交进git仓库**（已加入`.gitignore`），只能手工在服务器上创建。

| 变量名 | 是什么 | 从哪拿 |
|---|---|---|
| `DATABASE_URL` | MySQL连接串（含账号密码） | 腾讯云控制台→云数据库MySQL→你的实例→内网地址，账号密码是你创建实例时设置的（建议为生产单独建一个权限受限的数据库账号，不要用root） |
| `REDIS_URL` | Redis连接串 | 腾讯云控制台→云数据库Redis→你的实例→内网地址+密码 |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | 登录令牌签名密钥 | 自己生成随机字符串，命令：`openssl rand -base64 48`（在你电脑终端跑一下，复制结果），**不能用开发环境的change-me** |
| `AI_GATEWAY_INTERNAL_API_KEY` / `INTERNAL_API_KEY` | apps/api 和 apps/ai-service 两个服务之间的通行密钥，两边必须填一样的值 | 同样用`openssl rand -base64 32`生成一个随机值即可，不是从外部申请的 |
| `VOLCENGINE_API_KEY` / `VOLCENGINE_ENDPOINT_ID` | 火山引擎方舟(Ark)大模型的密钥 | 火山引擎控制台→方舟大模型服务→API Key管理 / 推理接入点。你手上已经有这个key，之前一直没做真实联调 |
| `MINIMAX_API_KEY` / `MINIMAX_GROUP_ID` | MiniMax大模型密钥（备用供应商） | MiniMax开放平台账号设置里 |

## 三、密钥存放原则

1. **绝不写进代码仓库**：所有真实密钥只存在于服务器本地的 `.env.prod` 文件，或者更安全的做法——用腾讯云"密钥管理系统KMS"或"云API密钥"托管（预算和精力有限的话，V1阶段直接用服务器本地文件也可以接受，只要做到下面第2点）。
2. **服务器文件权限收紧**：`.env.prod` 建议设置成只有部署用的系统账号能读，`chmod 600 .env.prod`。
3. **定期轮换**：JWT密钥和服务间共享密钥建议每半年至一年轮换一次；轮换JWT密钥会导致所有人重新登录，选业务低峰期操作。
4. **谁能看到密钥**：只有你（产品负责人）和实际登录服务器做部署的人应该能看到 `.env.prod` 的内容。AI开发助手在对话里**永远不应该也不会要求你把真实密钥粘贴到聊天记录里**——填密钥这一步必须由你直接在服务器上操作，这也是为什么"真实API Key端到端冒烟测试"这件事本轮还没做，需要你自己动手。

## 四、如果密钥泄露了怎么办

- 数据库密码泄露：立刻在腾讯云控制台重置数据库账号密码，同步更新服务器上的`.env.prod`并重启服务。
- JWT密钥泄露：立刻更换`JWT_ACCESS_SECRET`/`JWT_REFRESH_SECRET`并重启——效果等同于让所有人当前的登录状态失效，员工需要重新登录，这是预期代价，不是bug。
- AI供应商API Key泄露：立刻去火山引擎/MiniMax控制台吊销旧key、生成新key，同时检查该key的调用记录里有没有异常大量调用（可能被盗用产生费用）。
