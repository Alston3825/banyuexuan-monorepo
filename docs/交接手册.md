> 给**任何接手的 AI 助手/开发者**看的第一份文件。Claude Code 用不了时，用 Codex、Cursor、ChatGPT 等任何 AI Agent 打开本仓库，先读这份，再读 `AGENTS.md`（开发约定）和 `docs/进度快照.md`（自动更新的最新进度），就能继续开发。

## 一、一句话说明
多门店月子中心管理系统：客户/合同/房态/收款、母婴护理档案（含拍照 AI 识别纸质单）、库存采购、月子餐、人事、审批工作流、IoT 等。正式环境已上线运行：https://fanqieai.cc 。

**用户（产品负责人）不懂编程**：一律用**中文、通俗的话**沟通；每次改动后给出测试地址和账号；只有用户明确说“上线”才部署。

## 二、技术架构与目录
| 目录 | 内容 | 技术 |
|---|---|---|

- 数据库迁移：`apps/api/prisma/migrations/`（Prisma，按时间戳命名，只增不改旧文件）。
- 后端测试：`apps/api/test/*.e2e-spec.ts`（约 40 个文件，真实连库的端到端测试）。
- 修改前先读 `AGENTS.md`（= `CLAUDE.md`）里的界面/后端约定，这些都是用户明确提出过的做法。

## 三、本机怎么跑起来
```bash
git clone git@github.com:Alston3825/banyuexuan-monorepo.git && cd banyuexuan-monorepo
npm install
docker compose up -d                       # 本机 MySQL + Redis（docker-compose.yml）
cp apps/api/.env.example apps/api/.env      # 按注释填；本机数据库名 banyuexuan_dev
cd apps/api && npx prisma migrate deploy && npx prisma db seed && cd ../..
npm run dev:api     # http://localhost:3000/api/v1/health
npm run dev:web     # 页面 http://localhost:5173（用户习惯的测试地址是 5180）
```
- 种子账号：`admin`。种子密码来自环境变量 `SEED_DEV_PASSWORD`/`SEED_ADMIN_PASSWORD`，用户本机用的是 `change-me`。
- ai-service：`cd apps/ai-service && python -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/uvicorn main:app --port 8000`，密钥写 `apps/ai-service/.env`（见 `docs/环境与密钥管理手册.md`）。
- **后端测试**：`cd apps/api && npx jest --config test/jest-e2e.json --runInBand --forceExit`。**不要在 `banyuexuan_dev` 上跑**（里面是用户的真实测试数据），用独立库（如 `banyuexuan_e2e_s`，每次先删库重建，再 `prisma migrate deploy` + `prisma db seed`，用环境变量 `DATABASE_URL`、`SEED_ADMIN_PASSWORD=Passw0rd!23`、`SEED_DEV_PASSWORD=Passw0rd!23` 覆盖）。
- **前端发版前必须**：`cd apps/web && npx vue-tsc -b && npx vite build`（服务器构建就是这两步，缺一不可）。

## 四、线上环境与发布流程
- 服务器：腾讯云 Ubuntu，域名 `fanqieai.cc`，代码在 `~/banyuexuan`，容器 `banyuexuan-prod-{web,api,mysql,redis,ai-service}-1`，自建 MySQL/Redis（容器内）。
- SSH：登录用户 `ubuntu`（root 被拒），私钥文件在用户电脑 `~/Desktop/百度同步盘/AI 密匙/fanqieai1004.pem`（**私钥不在仓库里**，权限必须 600；用户会不定期更换，以用户最新给的为准）。服务器上用 docker 要加 `sudo`。
- 线上密钥在服务器 `~/banyuexuan/.env.prod`（**不在 GitHub**）。变量名清单见 `.env.prod.example`，说明见 `docs/环境与密钥管理手册.md`。
- **发布（仅当用户说“上线”）**，按顺序：
  1. 本机跑测试 + `vue-tsc -b && vite build`；
  2. `git push origin HEAD:main`；
  3. SSH 到服务器：`cd ~/banyuexuan && sudo bash scripts/backup-mysql.sh`（先备份）→ `git pull origin main` → `sudo bash scripts/deploy.sh`（自动跑迁移、构建、重启）；
  4. 验证：`sudo docker ps` 里 api 显示 healthy，`curl https://fanqieai.cc/api/v1/health` 返回 200。
- 线上数据是真实客户数据：**不要重置/清库；要读线上数据库前先征得用户同意**。

## 五、备份与“Claude 用不了”时的接手方式
三层备份，都不依赖 Claude：
| 内容 | 备份在哪 | 怎么更新 |
|---|---|---|
| **全部源代码、文档、迁移、本交接手册** | GitHub 私有仓库 `Alston3825/banyuexuan-monorepo`，`main` 分支 | 每次 `git push` 即同步；GitHub Action（`.github/workflows/daily-snapshot.yml`）每天北京时间 03:30 自动刷新 `docs/进度快照.md` 并提交 |
| **线上数据库 + 上传的文件（合同原件、护理照片）** | ① 服务器 `~/banyuexuan/backups/`，每天凌晨 3 点自动备份，留 14 天；② 用户 Mac 的 `~/Desktop/百度同步盘/伴月轩AI系统开发/线上备份/`（再同步到百度网盘），**加密**，每天 12:30 自动从服务器拉取一次，留 14 天 | `scripts/offsite-backup-pull.sh`（用户 Mac 上的定时任务）|
| **线上密钥配置 `.env.prod`** | 用户 Mac 本地 `~/伴月轩备份-密钥/`（不同步到网盘，仅本机）；建议用户另存进密码管理器 | 同上脚本每天拉一次 |
- 数据库备份是加密的（AES-256），解密口令保存在用户 Mac 的 `~/.banyuexuan-backup-pass`（**不在网盘、不在 GitHub**），请用户另存一份到密码管理器。口令丢了 = 备份无法还原。

### 换别的 AI Agent 继续开发（给用户的步骤）
1. 在电脑上 `git clone git@github.com:Alston3825/banyuexuan-monorepo.git`（或在新 AI 里直接打开该仓库）。
2. 对新 AI 说：“请先阅读仓库里的 `docs/交接手册.md`、`AGENTS.md`、`docs/进度快照.md`、`docs/待完善清单.md`，然后按里面的约定继续开发。我不懂编程，请用中文、讲人话。”
3. 需要上线时，把服务器私钥路径（`~/Desktop/百度同步盘/AI 密匙/fanqieai1004.pem`）告诉它，并明确说“上线”。

### 灾难恢复（服务器坏了/数据丢了）
1. 新服务器装好 Docker，`git clone` 本仓库到 `~/banyuexuan`，把备份的 `.env.prod` 放进去（`chmod 600`），`sudo bash scripts/deploy.sh`。
2. 还原数据库：解密 `*.sql.gz.enc` → `openssl enc -d -aes-256-cbc -pbkdf2 -in 文件.enc -pass file:$HOME/.banyuexuan-backup-pass | gunzip > restore.sql`，再 `sudo docker exec -i banyuexuan-prod-mysql-1 sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" 库名' < restore.sql`（库名见 `.env.prod` 的 `MYSQL_DATABASE`）。
3. 还原文件：把 `files-*.tar.gz` 解到 api 容器的 `/repo/apps/api/storage`。

## 九、给接手 AI 的工作要点（经验教训）
- 用户说“上线”之前不要部署；上线前必须先备份数据库。
- 不要在 `banyuexuan_dev`（用户真实测试数据）或线上库上跑测试/重置；e2e 一律独立库、**每次重建**（复用旧库会因残留数据产生假失败）。
- 前端改完必跑 `vue-tsc -b` 与 `vite build`；手机上看一遍（宽度 375px），界面要电脑和手机都好用（见 `AGENTS.md`）。
- 系统界面**只有浅色主题**（已声明 `color-scheme: light`），别引入深色样式。
- 单例定时任务（如物流自动刷新）要放在单例 provider 里，请求作用域的 provider 里不会启动。
- 新增数据库字段/权限点：写 Prisma 迁移；权限点同时加到 `apps/api/prisma/seed.ts` 和 `role-defaults.ts`。
- 密钥只能存在 `.env`/`.env.prod`，**绝不写进代码、文档或聊天**。
