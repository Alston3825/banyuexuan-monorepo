# 部署操作手册

给你（产品负责人）一份可以在已就绪的腾讯云服务器上照做的部署步骤。我没有你服务器的SSH访问权限，这一步需要你自己操作，或者后续把连接方式给到开发助手由它代为执行——但这属于"影响生产系统的操作"，按约定需要你明确同意后才会做。

**当前方案：数据库自建在服务器上（免费），不购买腾讯云托管的云数据库MySQL/Redis。** 这意味着MySQL/Redis就跑在这台服务器自己的Docker容器里，不需要额外花钱开云数据库实例；代价是"自动备份/高可用"这些云数据库自带的功能需要自己补——已经通过`scripts/backup-mysql.sh`（每天凌晨自动跑）解决了备份这一项，高可用（比如数据库单机故障自动切换）目前没有做，如果这台服务器本身宕机，数据库跟应用会一起不可用，这是用免费方案换来的已知取舍。

## 一、推荐路径：一键部署脚本

### 前置条件（你已确认就绪）

- 腾讯云轻量应用服务器/CVM，**建议4核8G起步**（比纯应用服务器的规格建议高一档，因为MySQL现在也跑在这台机器上，需要更多内存）；系统建议选 Ubuntu 22.04（脚本按 Debian/Ubuntu 系写的，装Docker和可选的HTTPS用到`apt-get`）
- 服务器已重置为纯净系统，能SSH登录（多数腾讯云镜像默认是root登录）
- 域名（可选）：如果这次先不接域名，直接用公网IP访问也可以，以后有域名了再补HTTPS

### 具体步骤

```bash
# 1. SSH登录服务器后，把代码拉下来（仓库地址换成你自己的）
git clone <你的仓库地址> banyuexuan
cd banyuexuan

# 2. 一键部署（必须root权限，因为要装Docker/装Nginx/注册定时任务）
sudo bash scripts/deploy.sh
```

跑起来之后脚本会依次自己完成：

1. 检查/安装 Docker
2. 交互式问你几个业务信息：租户名、门店名、管理员账号密码、（可选）域名——**只有这一步需要你手动输入**，其余全自动。管理员密码可以直接回车让脚本帮你生成一个强密码
3. 生成 `.env.prod`（所有密钥/密码自动生成，`chmod 600` 只有root能读）
4. 构建镜像、启动 api / ai-service / web / mysql / redis 五个容器
5. 等数据库就绪后自动执行数据库结构迁移（建表）
6. 自动创建你刚才填的管理员账号（写权限目录、角色、审批流程骨架等结构性配置）
7. 如果你填了域名：自动装nginx+certbot，申请免费的Let's Encrypt证书，配好HTTPS
8. 注册每天凌晨3点的数据库自动备份定时任务

跑完最后会打印访问地址和管理员账号密码——**密码只显示这一次，务必当场保存**。

### 跑完之后你还要做的一件事

腾讯云控制台 → 这台服务器 → 安全组，确认放行了 **80端口**（配了HTTPS的话还要放行 **443端口**）。这一步脚本做不了，是腾讯云控制台侧的网络策略，只有你自己能点。

### 以后怎么发布新版本

代码有更新后，在服务器上：

```bash
cd banyuexuan
git pull origin main
sudo bash scripts/deploy.sh
```

再跑一次同一个脚本就行——它是幂等的，已经生成过的密钥/密码/管理员账号不会重复生成或覆盖，只会重新构建镜像、重启容器、跑一遍数据库迁移（新增的表结构）和seed（新增的权限点，upsert语义不影响已有数据）。

## 二、手动方式（了解脚本具体做了什么，或者脚本某一步失败需要单独重跑时用）

### 1. 服务器一次性准备

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
```

防火墙/腾讯云安全组：开放80端口（HTTP）和443端口（HTTPS，如果配了域名）给公网；3000/8000/3306/6379端口**不要**对公网开放——api/ai-service/mysql/redis 都只在docker内部网络或回环地址上监听，这是`docker-compose.prod.yml`里特意的设计。

### 2. 配置生产环境变量

```bash
cp .env.prod.example .env.prod
chmod 600 .env.prod
vi .env.prod
```

每一项具体怎么填，`.env.prod.example` 里每行上面都有中文注释；密钥类的生成方式见文件内注释（`openssl rand ...`）。完整说明见 `docs/环境与密钥管理手册.md`。

### 3. 首次部署

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

这一步会：构建三个应用镜像（api/web/ai-service）→ 拉取mysql/redis镜像 → 启动全部五个容器 → api容器启动时自动跑 `prisma migrate deploy`（应用数据库结构）。**注意：这一步只建结构，不建数据**——数据库里此时还是空的，下一步手动跑一次种子脚本。

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod exec -T api sh -c \
  "NODE_ENV=production npx prisma db seed"
```

六个 `SEED_*` 变量（租户/门店/管理员账号）已经写在 `.env.prod` 里了（`env_file`会自动把它们传进api容器），不需要在这条命令上额外传。具体六个变量怎么填、为什么必须显式提供，见 `docs/生产数据库迁移与种子数据策略.md`。跑完这一步，你就有了一个真实的超级管理员账号，可以登录了。

### 4. 域名与HTTPS（免费方案：服务器自装 Certbot）

```bash
sudo apt-get update -y
sudo apt-get install -y nginx certbot python3-certbot-nginx
```

把 `web` 容器的端口映射从 `80:80` 改成 `127.0.0.1:8080:80`（建一个 `docker-compose.https.override.yml`，内容参考 `scripts/deploy.sh` 里自动生成的那一段），让宿主机nginx占住80/443，反代到容器的8080端口。然后：

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod -f docker-compose.https.override.yml up -d
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d <你的域名> --redirect --agree-tos
```

证书续期由certbot自带的定时任务自动处理，不需要你手动管理。**这一整套流程 `scripts/deploy.sh` 已经自动化了**，手动做仅供排查问题时参考。

> 备选方案：如果你后续改用腾讯云负载均衡(CLB)做HTTPS终止（不免费但更省心，证书续期腾讯云托管），把 `web` 服务的 `ports` 改回 `"80:80"`（不用host nginx这层），在CLB控制台申请证书转发到服务器80端口即可，两种方案二选一。

### 5. 验证部署是否成功

```bash
curl http://<服务器IP或域名>/api/v1/health
# 期望返回 {"status":"ok","service":"api",...}
```

浏览器打开域名/IP，应该看到登录页；用管理员账号登录，确认可以正常进入系统。

### 6. 日常运维命令

```bash
# 查看服务状态/日志
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f api

# 手动跑一次数据库备份（定时任务默认每天凌晨3点自动跑）
bash scripts/backup-mysql.sh

# 发布新版本（拉最新代码后重新构建）
git pull origin main
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

## 三、上线后需要你另外做的事（不是代码能自动完成的）

1. **真实API Key冒烟测试**：把火山引擎/MiniMax的真实key填进`.env.prod`后，重启ai-service容器（`docker compose -f docker-compose.prod.yml --env-file .env.prod up -d ai-service`），找一个真实客户咨询场景手动测一次AI客服，确认真的能拿到回复而不是降级提示。
2. **确认每日备份在正常跑**：部署几天后登录服务器看一眼 `backups/` 目录下有没有按天生成新的 `.sql.gz` 文件（`ls -lh backups/`），确认定时任务确实在跑，不要等到真出事故才发现备份没生效。备份文件默认只留在这台服务器本地——如果这台服务器本身出问题（硬盘损坏、被误删），本地备份也会一起丢，条件允许的话建议定期把 `backups/` 目录同步一份到别的地方（比如腾讯云COS对象存储，或者干脆定期下载到自己电脑），这一步脚本目前没有自动做。
3. **AI模型调用费用告警**：去火山引擎/MiniMax各自的控制台设置用量告警阈值（计划书风险登记册里提到的"大模型API调用费用失控"应对措施，这是在对应云平台控制台配置的，不是本仓库代码的一部分）。
4. **真正的P95性能统计**：等系统跑起来有真实员工使用一段时间后，可以考虑接入腾讯云的APM/前端监控产品，才能拿到计划书要求的"P95指标达标情况"这份数据（本轮的`性能基线报告.md`只是单次本地测量，说明见该报告）。
