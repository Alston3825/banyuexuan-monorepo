# 部署操作手册

给你（产品负责人）一份可以在已就绪的腾讯云服务器上照做的部署步骤。我没有你服务器的SSH访问权限，这一步需要你自己操作，或者后续把连接方式给到开发助手由它代为执行——但这属于"影响生产系统的操作"，按约定需要你明确同意后才会做。

## 前置条件（你已确认就绪）

- 腾讯云轻量应用服务器/CVM，建议2-4核8G起步（跟计划书里的规格建议一致）
- 域名已完成ICP备案并解析到服务器公网IP
- 腾讯云云数据库MySQL、云数据库Redis实例已开通（**不要**在应用服务器上自建MySQL/Redis容器，用腾讯云托管实例更省心，备份/高可用它帮你管）

## 一、服务器一次性准备

```bash
# 装 Docker + Docker Compose（Ubuntu/Debian示例，其他发行版参考腾讯云官方文档）
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 拉代码（需要服务器上配好能访问你GitHub仓库的凭证，或者直接用 git clone + 部署token）
git clone git@github.com:Alston3825/banyuexuan-monorepo.git
cd banyuexuan-monorepo
```

防火墙/腾讯云安全组：开放80端口（HTTP，用于健康检查/证书验证）和443端口（HTTPS）给公网；3000/8000端口**不要**对公网开放（api和ai-service只在docker内部网络里被访问，这是`docker-compose.prod.yml`里特意的设计）。

## 二、配置生产环境变量

```bash
cp .env.prod.example .env.prod
chmod 600 .env.prod
# 然后用 vi/nano 编辑 .env.prod，把里面的密码/密钥都填成真实值
# 详细每一项怎么填、去哪申请，见 docs/环境与密钥管理手册.md
vi .env.prod
```

## 三、首次部署

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

这一步会：构建三个镜像（api/web/ai-service）→ 启动容器 → api容器启动时自动跑 `prisma migrate deploy`（应用数据库结构）。**注意：这一步只建结构，不建数据**——数据库里此时还是空的，下一步手动跑一次种子脚本。

```bash
docker compose -f docker-compose.prod.yml exec api sh -c \
  "NODE_ENV=production SEED_TENANT_CODE=xxx SEED_TENANT_NAME=xxx SEED_STORE_CODE=xxx SEED_STORE_NAME=xxx SEED_ADMIN_USERNAME=xxx SEED_ADMIN_PASSWORD=xxx npx prisma db seed"
```

具体六个变量怎么填、为什么必须显式提供，见 `docs/生产数据库迁移与种子数据策略.md`。跑完这一步，你就有了一个真实的超级管理员账号，可以登录了。

## 四、域名与HTTPS

**推荐方案**：在腾讯云控制台给这台服务器挂一个负载均衡(CLB)或者用API网关，在那一层申请免费SSL证书并做HTTPS终止，转发到服务器的80端口（也就是`web`容器监听的端口）。这样证书续期由腾讯云托管，你不需要在服务器上自己维护证书文件和续期任务，长期免维护，比较适合"一人运维"场景。

如果不想为负载均衡额外付费，替代方案是在服务器上装 Certbot 用 Let's Encrypt 免费证书直接在服务器层终止HTTPS——这需要额外在服务器上装一层host nginx做证书终止再转发到`web`容器的80端口，涉及的配置比当前`docker-compose.prod.yml`多一层，如果你决定走这条路线，需要单独再让开发助手补一版host nginx配置（当前版本按"腾讯云CLB终止TLS"的推荐方案设计，源站容器本身只处理HTTP）。

## 五、验证部署是否成功

```bash
curl http://<服务器IP或域名>/api/v1/health
# 期望返回 {"status":"ok","service":"api",...}
```

浏览器打开域名，应该看到登录页；用第三步创建的超管账号登录，确认可以正常进入系统。

## 六、日常运维命令

```bash
# 查看服务状态/日志
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f api

# 发布新版本（拉最新代码后重新构建）
git pull origin main
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build

# 数据库结构有新迁移时，重启api容器会自动执行 prisma migrate deploy，不需要额外操作
```

## 七、上线后需要你另外做的事（不是代码能自动完成的）

1. **真实API Key冒烟测试**：把火山引擎/MiniMax的真实key填进`.env.prod`后，找一个真实客户咨询场景手动测一次AI客服，确认真的能拿到回复而不是503降级。
2. **数据库自动备份**：腾讯云云数据库控制台里开启自动备份策略（这是云数据库自带功能，不需要额外开发）。
3. **AI模型调用费用告警**：去火山引擎/MiniMax各自的控制台设置用量告警阈值（计划书风险登记册里提到的"大模型API调用费用失控"应对措施，这是在对应云平台控制台配置的，不是本仓库代码的一部分）。
4. **真正的P95性能统计**：等系统跑起来有真实员工使用一段时间后，可以考虑接入腾讯云的APM/前端监控产品，才能拿到计划书要求的"P95指标达标情况"这份数据（本轮的`性能基线报告.md`只是单次本地测量，说明见该报告）。
